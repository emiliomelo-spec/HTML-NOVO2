Documentos de Testes

Plano de teste

Um plano de teste organiza testes de um sistema para identificar erros e verificar se suas funcionalidades funcionam corretamente. Elementos principais: objetivo, escopo, casos de teste, resultados esperados e conclusão. Exemplo: testar login, pesquisa de produtos, carrinho e finalização de compra em um site.

Casos de teste

Casos de teste são procedimentos usados para verificar se uma funcionalidade de um sistema funciona corretamente. Exemplo: testar o login de um site, verificando se o usuário consegue entrar com e-mail e senha válidos.

Relatório de Incidentes de Testes

Relatório de Incidentes de Testes é um documento que registra erros encontrados durante os testes de um sistema, descrevendo o problema, sua gravidade e possíveis soluções.

Relatório de Resumo de Teste

Relatório de Resumo de Teste é um documento que apresenta os resultados finais dos testes de um sistema, indicando os testes realizados, os erros encontrados e a qualidade geral do software.

Elaboração do Caso de Teste

Conceito: é a criação de etapas para verificar se uma funcionalidade de um sistema funciona corretamente, comparando o resultado esperado com o resultado obtido.

Exemplos:

  • Login: verificar se o usuário consegue entrar com e-mail e senha válidos.
  • Pesquisa: verificar se o site exibe os produtos pesquisados.
  • Carrinho: verificar se o produto é adicionado corretamente.
  • Compra: verificar se o pedido é finalizado com sucesso.

Execução do Programa

Nessa etapa, execute-se o programa ou o código utilizando os atributos do HTML, como classe, id, título, texto, de acordo com o plano de teste e com os casos de testes elaborados, objetivando identificar os elementos da página são semelhantes às interações do usuário. É por meio dessa interação que é possível obter os resultados e a coleta de erros.

Monitoramento e Contro

Durante a execução do teste, os dados são monitorados e selecionados aleatoriamente. fatores que influenciam o erro. Como resultado dessa etapa, sugere-se a elaboração de um documento chamado relatório de incidente de teste, que deve descrever todos os eventos ocorridos, viabilizando, posteriormente, a análise pela equipe de desenvolvimento, responsável por realizar a correção dessas falhas.

Avaliação dos Resultados

Nessa etapa, um equipe de desenvolvimento avaliará o erro, buscando compreender o que o ocasionou, por exemplo, erro de sistema, de código, de internet, de hardware, para, assim, corrige-lo. É normal que aplicações apresentem erros de modo não consecutivo. Alguns fatores podem motivar a ocorrência de erros, como rede, requisições ou caso o sistema esteja consumindo uma API que está fora do ar por razões de atualização, de implantação de sistema ou do serviço do sistema que esteja hospedado, ou ainda, em razão de uma atualização ou correção de erro no site que está em ambiente de produção.

Comunicação com a equipe de automoção de testes

A comunicação com a equipe de automação de testes consiste em compartilhar informações sobre testes automatizados, erros encontrados, resultados obtidos e melhorias necessárias, garantindo a qualidade e o bom funcionamento do sistema.
